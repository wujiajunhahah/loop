# W·HERE 黑客松 Demo Runbook

这份 runbook 是现场操作手册，不是产品介绍。演示前只使用已经通过验证的 commit、实际页面和合成 Demo 数据。

[返回 README](../README.md) · [隐私安全](PRIVACY_SECURITY.md) · [资产权利](ASSET_RIGHTS.md) · [视频工作流](VIDEO_WORKFLOW.md)

## Go / No-Go

演示前满足全部条件才进入 Go：

- 已运行 `npm run verify`，并记录实际测试数量、typecheck、build 和 `git diff --check` 结果。
- 已在桌面和 `390 x 844` 视口打开首页、接收者入口和 Echo Map 入口。
- 当前 Demo 使用 Mei → Lin 的合成雨天案例，没有真实悼念内容或私人数据。
- 浏览器可以访问本地 Vite 地址，实际端口已记录。
- 已准备不用硬件、不用网络、不用 API Key 的软件路径。
- 若准备了宣传视频，已确认 MP4 可播放；没有视频时仍能完成现场产品 Demo。

任一条件不满足就 No-Go：不要在现场临时引入依赖、切换模型、连接真实硬件或修改产品源码。

## 两分钟讲解与操作

### 0:00–0:20 先讲清楚边界

> W·HERE 不是数字复活，也不是人格克隆。它让人在生前留下经过本人确认、关系专属、有来源的内容；未来只有接收者主动进入时，过去才回应今天。

### 0:20–0:40 打开接收者入口

1. 首页点击 **收到回应**。
2. 点击 **主动进入**。
3. 选择 **进入 Echo Map 旅程**。
4. 强度选择 `glimmer`。

强调：系统不会主动播放，也不会在接收者没有进入时推送。

### 0:40–1:05 查看来源与中立动作

1. 检查雨天节点和 `同一把伞下的雨`。
2. 点击 **查看这段旅程**。
3. 展示来源 Context、Asset 和触发方式。
4. 点击 **采用中立动作**，再点击 **我已经做了**。

强调：中立动作不是 Mei 的留言，也不是 AI 生成内容。

### 1:05–1:35 展示真实来源和 AI 边界

1. 点击 **打开原始内容**。
2. 展示 **真实原始来源**。
3. 展示 **AI 生成 · 明确标记**。
4. 指出 Context、Asset、生成模式和“仅主动进入”。

强调：原始内容不会被覆盖，AI 不能新增 Mei 没有留下的事实。

### 1:35–1:55 生成 postcard

1. 点击 **继续**。
2. 输入：`今天下雨了，我又想起那把伞。`
3. 点击 **保存并生成明信片**。
4. 检查原始来源、AI 整理、Lin 的回应和 Artifact ID。

### 1:55–2:00 收尾

> 这是一份有来源、有限制、由接收者主动打开的回应。过去的记忆，回应现在的生活。

## 失败恢复

| 情况 | 处理 |
| --- | --- |
| 页面状态卡住 | 回到 `#/recipient`，重新主动进入；不要声称已完成 |
| Echo Map 要求身份确认 | 这是正确的安全行为，从 `#/recipient` 重新进入 |
| 明信片生成失败 | 点击重试；仍失败时展示错误状态和来源，不跳过状态宣布完成 |
| 页面刷新后状态消失 | 说明当前是内存 Demo，重新走主动进入流程 |
| 端口被占用 | 使用 Vite 终端显示的新端口，不修改脚本 |
| 现场没有网络 | 使用已经启动的本地 Demo；不临时调用云端 AI |
| 现场没有硬件 | 直接展示软件入口；硬件不是核心闭环前提 |

重置方式：关闭当前浏览器标签页，重新打开 `http://127.0.0.1:<实际端口>/#/`。当前状态只在浏览器内存中，刷新会恢复预置 Demo。

## 评委问答边界

- **这是数字复活吗？** 不是。系统只使用本人确认过的来源，并明确标记 AI 整理。
- **会主动提醒或推送吗？** 当前默认 `pull_only`，接收者必须主动进入。
- **是真实大模型吗？** 当前是确定性离线 Demo，后续真实模型必须继续经过授权、来源和边界控制。
- **数据保存在哪里？** 当前仅保存在浏览器内存，刷新会重置；不是生产存储方案。
- **能不能代表一个人自由聊天？** 不能。它不能无来源补事实，也不是高自由度人格克隆。
- **硬件在哪里？** 硬件是可选入口，软件闭环可以独立完成。
